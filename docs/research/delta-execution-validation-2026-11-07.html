3. Twenty crypto pairs work on one public connection

The VM probe selected the 20 highest-turnover crypto perpetuals, excluding tokenized stocks and metals using the bot’s market classifier. It captured 11,733 depth messages, 35,643 quote messages and 1,453 trade messages in three minutes. There were no reported subscription errors, sequence/checksum failures or dropped capture events.

At fixed one-second sampling points after warmup: 3,560 / 3,560 quotes were fresh; 3,121 / 3,560 depth samples were under 1 second old (87.7%); 3,557 / 3,560 were under 5 seconds (99.9%). All were under 10 seconds. Quiet books explain why a blanket one-second depth gate would reduce coverage. This test does not justify treating a ten-second-old book as a guaranteed executable price.

The existing 32 MiB diagnostic ring cannot serve as a full-day multi-pair research archive. Recording must use bounded segments, periodic full-book checkpoints and explicit coverage manifests. Simply increasing the symbol list is insufficient.

4. What the tests support building

  1. Deploy the verified recovery fixes. They resolve reproducible faults. Preserve $150 sizing, the 3% stop-risk ceiling and the 6× risk-to-cost rule.
  2. Record executable exits for every held and pending paper pair. Use timestamped, validated depth when available. Keep a clearly identified quote-based estimate when depth is unavailable; missing depth must not prevent risk reduction. Record partial depth and unpriced remainder explicitly.
  3. Collect complete signal-to-exit comparisons before changing TP/SL rules. Bind the policy at entry. Compare the existing trigger with a causal tape trigger, then compare market and maker routes separately on the same signals. Hold scanner selection fixed.
  4. Promote an exit policy only on held-out net results. Require fees, funding, slippage, partial fills, drawdown and count alongside average R. A quote correction alone will usually lower apparent paper profit; that improves measurement, not trading edge.

The new research exit pricer and validation CLI are tested locally. They are not wired into the production fill engine. No additional gate, pair exclusion, stop widening or target change was enabled.

5. Reproduce and inspect

Read-only tools are saved with the repository. Run the export on a host that can read the database and the capture on the VM for comparable latency. Both avoid application startup and credentials.

python3 ops/research/export-execution.py --db /opt/vnedge/data/vnedge.db --days 7 --out /tmp/exits.json
node ops/research/capture-execution.mjs --seconds 180 --out /tmp/public.json.gz
node server/src/cli/validate-execution.ts --quotes /tmp/exits.json --capture /tmp/public.json.gz --out /tmp/results.json

Machine-readable results and input hashes. Original raw snapshots and before/after test logs are retained in this chat’s work/delta-execution-validation-20261107 directory. Public depth is reconstructed in receipt order and validated with the same checksum/sequence implementation as the bot. No future book is used to price an earlier sample.

Exchange reference: Delta India API documentation for timestamps, depth and contract sizes; Delta fees for notional-based charges and GST. The historical comparison uses each recorded order’s actual effective fee rate, including a recorded zero fee if present.
